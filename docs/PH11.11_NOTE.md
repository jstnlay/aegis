# PH11.11 — Responsive and Accessibility

**Status:** implementation complete and regression-verified.
**Browser/layout verification: NOT PERFORMED.** See [§9](#9-limitations).

## 1. What this phase delivered

Six waves, in the order the plan sets out. Every item is in the current tree; the
commit is not created (PH11.15).

| Wave | Outcome |
|---|---|
| 1 — shared primitives | `CardTitle` is a heading; one `h1` per document; `EmptyState` announces; stable page-size id; dialogs cap their height; `SelectTrigger` fills its column; `TableCell` wraps by default |
| 2 — keyboard/focus | `main` focused on route change; mobile drawer Escape/focus/inert; `ErrorBoundary` fallback focused; Change Password confirmation focused; real tablist on three admin pages |
| 3 — forms | `Field`/`ChoiceField` promoted out of `AdminAcademicsPage` and applied |
| 4 — state honesty | loading, failure and no-data are three distinct states on every dashboard |
| 5 — responsive | grid `min-w-0`, chart tick gaps, table captions in valid positions, `scope="col"` on hand-rolled tables |
| 6 — carry-forward | duplicate form ids; score unit; session expiry explainable; `ParentSupportRoute` states |

Baseline at `d094e53` was 615 tests / 37 files. This phase leaves
**666 tests / 41 files**, all passing.

## 2. Wave 1 — shared primitives

### 2.1 `CardTitle` is a heading

`CardTitle` rendered a `<div>`, so no card title in the application — "Average
Grade", "Risk Distribution", "Profile", "Linked Students" — appeared in the
heading outline at all. It now renders `<h3>` by default, which is the correct
depth for a titled region inside a page, with `as` for callers that need a
different level and `as="div"` for the cards that genuinely are not sections.

Classes are unchanged, so nothing moved.

### 2.2 One `h1` per document

`Header` renders the page title on every in-shell route, so it is the one place
that can own the document's top-level heading. Every page's own title moved from
`h1` to `h2`, and section headings below them from `h2` to `h3`. The twenty-nine
in-shell pages previously each carried two `h1`s — one in the header and one on
the page. `LoginPage`, `ChangePasswordPage` and `NotFoundPage` are outside the
shell and keep their own `h1`.

Test assertions were updated to pin the new level rather than dropping the level
check, which is the point of those assertions.

### 2.3 `EmptyState` announces itself

`LoadingState` announced and `ErrorNote` announced; `EmptyState` was silent, so
the polite end of a request was the one outcome a screen reader never heard. It
now carries `role="status"` — never `alert`, because nothing failed.

### 2.4 Stable page-size control id

`useId`, not the row count. PH11.9 derived the id from `totalCount` and assumed
it was unique per table; two tables on one screen with the same number of rows
produced the same `<label for>` and the same `<select id>`.

### 2.5 Dialog height

`max-h-[85svh] overflow-y-auto` moved into `DialogContent`. Six call sites already
carried `max-h-[90vh] overflow-y-auto` and three did not; because the content is
`position: fixed`, a dialog taller than a short or landscape viewport pushed its
footer buttons past the bottom edge with no way to scroll to them. `svh` rather
than `vh` so the cap is measured against the small viewport on mobile browsers.

### 2.6 `SelectTrigger` fills its column

`w-fit` → `w-full`, plus `min-w-0` on the value so a long selection ellipsises
instead of widening the control. `SelectContent` gained
`max-w-(--radix-select-content-available-width,100vw)`: the list is
`overflow-x-hidden`, so an option wider than the popper — a real case, since roster
options render `Lastname, Firstname — STU-2024-000123` — was cut with no way to
reach the tail.

### 2.7 `TableCell` wraps by default

`whitespace-nowrap` was removed from the base class and is now opt-in per cell.
It was right for codes, numbers and dates, and wrong for free text: a CMS
announcement body, a notification message or a teacher's remarks rendered as one
unbroken line whose width is the length of the text, which made the table wider
than any amount of horizontal scrolling usefully serves. Callers that want the old
behaviour ask for it through `DataTableColumn.cellClassName`.

## 3. Wave 2 — keyboard and focus

- **`main` focused after route changes.** A client-side navigation replaces the
  content without a page load, so focus stayed on the link that was activated — in
  a document that no longer contained it. Not applied on first render, which would
  steal focus from whatever opened the shell.
- **Mobile drawer.** `aria-expanded` and `aria-controls` on the hamburger, Escape
  closes it, focus returns to the trigger, and the off-canvas `<nav>` is `inert`
  while it is closed *at narrow widths*. The width check matters: `inert` is a DOM
  attribute with no responsive variant, so applying it purely on `open` would strip
  the navigation from the tab order on the one layout where it is permanently
  visible.
- **`ErrorBoundary` fallback focused.** `role="alert"` announced the failure but
  focus had fallen to `<body>` after the subtree unmounted.
- **Change Password confirmation focused.** Setting `success` unmounted the form
  and took the focused submit button with it; the panel now announces via
  `role="status"` and takes focus on its heading.
- **`AdminCmsPage` tab focus.** Its tabs were hand-rolled `<button>`s with no
  `focus-visible:` rule at all — the only one of the three admin tab strips not
  using the shared `Button`.

### 3.1 One `Tabs` component

`AdminAcademicsPage`, `AdminDataPage` and `AdminCmsPage` each declared
`role="tablist"` with `role="tab"` children and stopped. Missing: `aria-controls`,
a real `role="tabpanel"` for the content, arrow-key navigation (reaching the
seventh tab meant seven Tab presses), roving tabindex, and — on the CMS page — any
visible focus indicator. `components/ui/tabs.tsx` now serves all three. Panels are
declared rather than inferred, so `aria-controls` resolves by construction.

## 4. Wave 3 — forms

`Field`/`ChoiceField` were promoted out of `AdminAcademicsPage`, which was the only
implementation in the application satisfying PH11.2 §16.5 in full, and applied to
`AdminUsersPage`, `ConsultationsPage`, `InterventionsPage` and `RiskAlertsPage`.

One rule is worth recording because it is easy to get wrong twice: **the required
asterisk is a sibling of `<label>`, never a child.** An element inside a label —
even one marked `aria-hidden` — is still part of the label's text content, so the
control's accessible name becomes "Name *" and every announcement states the
requirement twice. `aria-required` on the control and the visual asterisk carry the
requirement separately; the label stays exactly the field's name.

Forms that could not adopt the shared component say why in a comment: the faculty
grade-encode form keeps its own labels because two of its selects are `disabled`
until an assignment is chosen and their placeholders explain *why*, and
`ChoiceField` has neither `disabled` nor a placeholder prop.

## 5. Wave 4 — state honesty

This was the largest remaining defect class and the one with real consequences.

**What was wrong.** `formatCount(null)` and `formatPercent(null)` render `"N/A"`,
which asserts *the backend reported no figure*. Every dashboard fell back to that
on two occasions where the backend had reported nothing at all:

- while the request was in flight, so the first paint of every dashboard asserted
  three or four measurements that had not been made;
- after the request **failed**, so a network error was reported to a parent,
  student, counselor or administrator as an absence of data.

`AdminAnalyticsPage`, `AdminAttendancePage`, `AdminDashboard`,
`ParentAcademicsPage`, `GuidanceDashboard`, `StudentDashboard` and
`FacultyDashboard` all had this. `AdminAttendancePage` was the worst: its totals
are `reduce`d over a fallback empty array, so a failed summary rendered
Present `0`, Late `0`, Absent `0` — four numbers presented as measurements.

**Second defect on the same surfaces.** Every loading state was one or more bare
`Skeleton` bars: grey rectangles with no role, no state and no text. A screen-reader
user arriving on a dashboard heard the page title and nothing about the figures
still arriving.

**Third defect.** Several failures were rendered as muted `<p>` lines sitting
directly above the corresponding empty-state line, and the two were visually
identical and both silent. `GuidanceDashboard` told a counselor there were "No risk
alerts" when the request had failed.

**The fix.** `PendingRegion` / `PendingMetric` wrap a skeleton *in place* — the
visual language is unchanged and the region gains `role="status"`, `aria-busy` and
a visually-hidden label naming what is awaited. `UnavailableMetric` is the third
state. Failures now render `ErrorNote` (`role="alert"`). A metric row reads from
one request, so its failure note is rendered once rather than once per tile.

`isFetching` → `isLoading` on every dashboard surface: `isFetching` stays true
through a background refetch, so refreshing a page replaced figures already on
screen with grey bars and then restored them.

### 5.1 A defect found while doing this

`ParentAcademicsPage` passed no error state to its attendance-summary card at all.
PH11.10 had already fixed the neighbouring defect (the record table being handed
the *summary*'s error); the summary card itself still fell through to its empty
branch on failure and told a parent "No attendance summary available" — a claim
about their child's attendance drawn from a request that failed. Now `summaryError`
is threaded through and the three grade/summary cards are independent, because the
three requests are.

## 6. Wave 5 — responsive specifics

- **The `AdminAcademicsPage` grid-clipping claim was not proven, so nothing was
  changed on the strength of it.** jsdom performs no layout; no test in this
  repository can prove a grid clips. What *is* a source-level fact is the
  mechanism: a grid item's default `min-width` is `auto`, which resolves to its
  content's min-content width, so a field in a narrow track refuses to shrink
  below its widest part. `Field` and `ChoiceField` now carry `min-w-0` on their
  wrapper, which is what removes the mechanism. The grading-period form
  (`sm:grid-cols-5` with two `type="date"` inputs) is the concrete case.
  **This is a reasoned fix, not a measured one.**
- **Chart tick gaps.** `minTickGap` added to the four charts whose category labels
  are free text. Without it Recharts overlapped them at narrow widths into an
  unreadable band. Nothing is lost by dropping a tick: every value remains in the
  tooltip and the full set is named in the frame's `aria-label`.
- **Table captions.** `AttendancePage`'s record-table caption was the *last* child
  of `<table>`, which is not a valid position — the HTML parser expects it first.
  Moved. Captions were also added to the two tables that had none, and
  `scope="col"` to every hand-rolled `TableHead` in the file.
  `scrollLabel` added where a table can exceed a phone's width, which is what makes
  the horizontal overflow reachable from the keyboard rather than only by dragging.

## 7. Wave 6 — carry-forward correctness

- **`AssessmentsPage` duplicate static ids.** `AddQuestionForm` renders once per
  draft assessment from inside a `.map()`, and its five controls used static ids
  (`question-text`, `question-type`, …). With two drafts on screen each id existed
  twice and every `<label for>` resolved to the first instance. Ids are now derived
  from the assessment id. Two regression tests cover it, one of which types into
  the second draft and asserts the first is untouched.
- **`SectionPerformanceChart` score unit.** `grade_average` is the mean of
  `Grade.score`, a raw 0–100 point value (PH11.7). The bar's label went through
  `formatPercent` and printed "85.0%" for a score of 85.00 out of 100 — on the one
  chart whose own description already said "as points out of 100". Now
  `formatScoreValue`, which every other score label in the app uses.
- **Session expiry is now explainable.** Expiry and sign-out were
  indistinguishable: both cleared the tokens, both set `unauthenticated`, both
  landed on `/login`, and the sign-in page said nothing. `AuthContext` now exposes
  `sessionExpired`, which `LoginPage` renders as a polite status, cleared as soon as
  the user signs in.
  **This path also did not clear the query cache**, while `logout` does. Every query
  key in the app is role-scoped but not user-scoped, so the next person to sign in
  on that browser could have been served the previous user's cached dashboards from
  react-query's memory cache until each happened to refetch. Now cleared.
- **`ParentSupportRoute` loading/failure/empty.** `linked` fell back to `[]`, so the
  page rendered an empty select and then "Choose a linked student above" in all
  three cases — an instruction to operate a control with nothing in it, and the
  identical page after a failure. The three states are separated.

## 8. Defect found and fixed during this phase, not in the plan

`AdminUsersPage`'s "Initial password" field was `type="password"` as a hand-rolled
`<Input>`. When PH11.11 moved it onto the shared `Field`, the component's `type`
union (`"text" | "date" | "number"`) silently downgraded it to `type="text"` —
unmasking an administrator's initial password in plain sight. `Field` now accepts
`"password"`. Admitting a form to a shared component must not cost it a property it
had; this is the failure mode that produced it, and it is worth the line.

## 9. Limitations

**No browser or layout verification was performed, and none was added.** jsdom
performs no layout and reports every element's box as zero, so:

- no test here can prove a grid clipped, or that `min-w-0` stopped it — the fix in
  §6 is reasoned from the CSS mechanism, not measured;
- no test here can read the text Recharts renders inside a chart. The
  `SectionPerformanceChart` assertions cover the unit contract on the accessible
  label and description, and the formatter itself has its own test; the rendered bar
  label needs a real browser;
- `matchMedia` is stubbed in the `AppShell` tests, so the drawer's `inert` at narrow
  width is verified against a stubbed viewport, not a resized one.

No new a11y or browser tooling was added, per the plan. No axe-core, no Playwright.

**Not changed, deliberately.** Data tables still scroll horizontally on mobile and
were not converted to cards. The ~500 kB chunk advisory from `npm run build` is
pre-existing and out of scope. The `>500kB` warning is unchanged from PH11.9.

## 10. Intentional non-goals

- No backend, database, CMS, API-contract or AI change. `sessionExpired` is
  presentation state in a frontend context; nothing about the refresh contract moved.
- No dependency added or removed.
- No redesign. No new colour system, no framework, no gradients or decorative UI.
- No `React.lazy` or bundle work.
- No test weakened or deleted. Two assertions were re-scoped where a change made a
  loose text match genuinely ambiguous (`AdminDashboard`, `StudentDashboard`,
  `FacultyDashboard` now match the *heading*, which is a stronger claim than the text
  match they replaced), and two route markers in `routes.test.tsx` follow a copy
  change in `ParentSupportRoute`. Every such change is commented at the site with
  what changed and why the assertion is not weaker.
