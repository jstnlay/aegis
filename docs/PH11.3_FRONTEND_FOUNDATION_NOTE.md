# PH11.3 — Frontend Foundation (Implementation Note)

Status: **complete** · Owner: frontend track · Scope;locked to `frontend/` for UI
code; the API contract and backend are untouched.

## 1. Goal

Stand up the AEGIS frontend on an approved technology stack, wire the frozen
API contract (tokens, `/me`, onboarding gate), and ship a shared application
shell plus placeholder routes — verified by render tests, type-check, lint, and
a production build.

## 2. Approved stack (locked)

| Layer        | Choice                                   |
| ------------ | ---------------------------------------- |
| Framework    | React 19 + TypeScript (strict) + Vite 8  |
| Routing      | React Router v7 (`createBrowserRouter`)  |
| Server state | TanStack Query v5                        |
| Forms        | react-hook-form v7                       |
| UI layer     | Radix UI primitives (unified `radix-ui`) |
| Styling      | Tailwind CSS v4 + shadcn/ui (nova style) |
| Lint/Format  | ESLint (flat) + Prettier (no semi)       |
| Verification| Node smoke render + `tsc` + `eslint` + `vite build` |

Tier-2 libraries (Recharts, react-table, polymorphic components, MSW) are
**explicitly deferred** — nothing was added speculatively. React 19 was kept
over 18 per the approved roadmap.

### 3.4 Architecture (Steps 12, 14)
```
src/types/        mirrors of the frozen backend contract (auth + pagination)
src/lib/          api client, token storage, error normalizer, roles, query client
src/features/auth AuthProvider (state machine), api wrappers, route guards
src/components/layout  AppShell (one shell for all five roles), Sidebar, Header,
                       SkipLink, LoadingScreen
src/routes/       route table (library mode), router, placeholder pages
```
- **Auth state machine:** `loading → unauthenticated | authenticated | restricted`
  where `restricted` = the PH8.7 `must_change_password` gate.
- **Silent refresh:** the backend rotates both tokens
  (`ROTATE_REFRESH_TOKENS=True`, PH10), so `lib/api.ts` persists the new pair
  on refresh and retries the original request once. Single-flight; on ultimate
  failure `onSessionExpired` clears state.
- **Error normalization:** `lib/error.ts` maps the frozen envelope
  `{ success:false, error:{code,message,details} }` into one typed object; a
  401 with message "Password change required." is detected specially.
- **Guards:** `ProtectedRoute` (auth boundary) and `RequireRole` (UX only —
  backend stays authoritative).

### 3.5 Placeholders (Steps 16–18)
- `/login` — branded sign-in placeholder (PH11.4 implements the flow).
- `/change-password` — onboarding-gate placeholder.
- `AppShell` HPIs the dark sidebar, top bar (user chip + role), skip link, and
  a shared Dashboard placeholder showing the session role.

## 4. Verification (Step 19)

```bash
npm run format:check  # Prettier clean
npm run typecheck     # tsc -b --force clean
npm run lint          # ESLint clean (0 errors, 0 warnings)
npm run build         # tsc -b && vite build clean
npm run smoke         # SSR render asserts for /login, /change-password, 404, AppShell — PASSED
```

Smoke uses `react-dom/server` with a memory router in Node (no browser, no MSW —
no API calls are made by the placeholders; the API layer is unit-reviewable but
untested by render).

## 5. Deviations & decisions

- `scripts/` (smoke harness) and `vite.config.ts` excluded from the app
  type-check project; the smoke bundle is built with esbuild to CJS so
  `react-dom/server` can `require("util")` in Node.
- `radix-ui` unified package is used (the nova preset default), not the
  per-repo `@radix-ui/*` packages of the older styles.
- `form` pulled from the `default` registry item because the `radix-nova`
  registry entry returns no files.
- Dark mode and the maroon header variant are out of scope for v1 (light-only
  per PH11.2 $19.3).
- No speculative route trees, dashboards, charts, or data tables — their
  libraries are deferred to the phases that need them.

## 6. Next phase hooks

- Password onboarding consumes `useAuth().changePassword` (restricted state).
- Role dashboards slot into `routes.tsx` under the `AppShell` layout;
