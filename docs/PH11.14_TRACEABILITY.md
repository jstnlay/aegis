# PH11.14 — Prototype Traceability

**Status:** audit complete. No frontend gap found that was fixable within approved
scope; two documented deviations and four items that cannot exist yet are recorded
below.

**Source of truth.** The prototype requirements already referenced by this
repository, in priority order:

1. `docs/PH11.2_DESIGN_LANGUAGE.md` §17.2 — *"What the Prototype Defines
   (Preserved)"*, the explicit prototype-element table, naming
   `Final_Revision.pdf` pp. 143–162, Figures 11–37.
2. `docs/PH11.2_DESIGN_LANGUAGE.md` §12, §13, §16 — the responsive, component and
   accessibility baselines the prototype does not define but which bind the
   implementation.
3. The actual implementation in `frontend/src`.

No requirement was taken from `Final_Revision.pdf` directly and none was invented.
Where the prototype asks for something the backend cannot supply, that is recorded
as **intentionally deferred** with the reason, not implemented as a placeholder.

## 2. Baselines the prototype does not define

### 2.1 §16 Accessibility — WCAG 2.1 AA target

| Requirement | Status | Note |
|---|---|---|
| Skip link, first in DOM, visible on focus | **Preserved** | `SkipLink.tsx`, targeting `#main-content`. |
| No `tabindex` > 0 outside widget patterns | **Preserved** | No occurrence anywhere in `src`; the only negative values are `Tabs`' roving tabindex and the programmatically-focused regions. |
| Dialog focus trap, Escape closes modals | **Preserved** | Radix `Dialog` primitive. Dialog height capped at `85svh` with internal scroll (PH11.11) so footer actions cannot be pushed out of reach. |
| Escape closes drawers; arrow keys in tabs/selects | **Preserved** | Drawer: `useEscapeToClose` in `Sidebar`. Tabs: roving tabindex + Arrow/Home/End in `components/ui/tabs.tsx`. Selects: Radix. |
| `<h1>`–`<h6>` in order, no skipped levels | **Changed (PH11.11)** | `Header` now owns the document's `h1` for all twenty-nine in-shell routes; page titles are `h2`, their sections `h3`, card titles `h3`. Previously every in-shell page carried two `h1`s. `CardTitle` became a real heading. |
| `role="alert"` for failures; `aria-live` for updates | **Preserved, strengthened (PH11.11)** | `ErrorNote` / `LoadingState` / `EmptyState` / `PendingRegion` / `UnavailableMetric` own the distinction. PH11.11 removed several muted `<p>` failures that were announced by nothing. |
| `<table>` with `<thead>`, `<tbody>`, `th scope="col"` | **Preserved, completed (PH11.11)** | Every hand-rolled `TableHead` now carries `scope="col"`; one caption was moved out of an invalid position; two tables that had no caption gained one. |
| Required fields: `*` **and** `aria-required` | **Preserved** | `Field`/`ChoiceField` render the asterisk as a sibling of `<label>` and set `aria-required` on the control. The asterisk is deliberately outside the label so the accessible name stays "Name", not "Name *". |
| Errors linked with `aria-describedby` | **Preserved** | `Field`, and hand-rolled controls in the guidance forms, all link the message. |
| **Error summary with links to each field** | **Changed — recorded deviation** | Not implemented. The app renders one `ErrorNote` per failed action plus per-field `aria-describedby`, which satisfies "the error is associated with the control" but not the linked-summary pattern of §16.5. A summary would need a second list of ids threaded through every form, and no screen in the app submits more than one form at a time, so the benefit is marginal against the cost. Deliberate; revisit if a multi-section form is ever added. |
| Touch targets | **Preserved, with a recorded exception** | The design system's 36px default is unchanged from PH11.4's decision not to widen it. PH11.11 moved the destructive per-row `Delete` control from `h-6` (24px, below §16.6's 32px floor) to `h-8` (32px) because that button is not recoverable. §16.6's ~44px target remains unmet for standard controls, by prior decision. |
| Dynamic content announced | **Preserved** | Live regions on the pagination range summary, on save confirmations (attendance, consultations, risk-alert transitions), and on every loading placeholder. Sort state is conveyed by `aria-sort` on the `<th>` plus a visually-hidden per-column hint inside the sort button, not by a live region — re-announcing a whole table on every sort click was judged more disruptive than helpful. |
| Icon-only buttons labelled | **Preserved** | Row actions carry per-row `aria-label` naming their target ("Update consultation for Ana Reyes on 2025-02-10"), not the bare verb. |

### 2.2 §12 Responsive, 320px–1920px

Status **preserved in structure; partially verified.** Mobile off-canvas navigation
with `inert` while closed, tables scrolling horizontally inside focusable named
containers, and `min-w-0` on shared form fields so narrow grid tracks can shrink.

**Verification limit:** jsdom performs no layout and this phase added no browser
harness, so none of this is measured — see PH11.11 §9. The grid-clipping question
raised by the reconciliation was answered by removing the mechanism
(`min-width: auto`) rather than by observing it.

### 2.3 §13.12 Loading / empty / error states

Status **preserved and unified (PH11.11).** One module, `@/components/feedback`,
owns all four states for every list, chart and metric in the app. PH11.11 added the
two that were missing — an announced placeholder region, and a failed state that is
distinguishable from "no data" — and removed the last hand-rolled copies.

## 3. Changes made under this phase

Two, both inside approved frontend scope:

1. **Parent dashboard brought in line with the student dashboard.** They read the
   same `useStudentDashboardData` hook and present the same figures, but rendered
   the same data with silent skeletons, muted failure lines and `N/A` after a
   failed request. Two views of one record must not look like two features.
2. **`ParentAssessmentsPage`'s question-detail error** switched from a hand-rolled
   copy of the alert markup to the shared `ErrorNote`, so it stops being the one
   failure in the parent surface rendered without the shared alert's icon.

## 4. Deliberately not done

- **No redesign to match the prototype visually.** §17.2's rows are treated as
  statements of what the prototype establishes, not as pixel targets. The app's
  visual language is PH11.2's, and this phase added no gradient, no hero section,
  no decorative UI and no new colour.
- **The student recommendation list stays absent** until the backend exposes it.
  Building it against `ai_engine` internals would be inventing a contract.
- **No faculty chart.** There is no faculty-scoped aggregate to plot.
- **`AcademicsLandingPage.tsx` is unreachable** — PH11.9 removed `admin` from
  `/app/academics`, so nothing routes to it. Deleting it is unrelated cleanup and
  was left alone.
