## 1. PH11.12 — Visual / anti-slop QA

Scope: all five role dashboards and the PH11.7–PH11.11 surfaces. Only real issues
were touched. Nothing was added: no gradient, no glassmorphism, no hero section,
no decorative UI, no new colour system, no new framework.

The mechanical detector over the whole source tree is clean:

```
npx impeccable detect --json src   ->  []   (exit 0)
```

Everything below came from reading the surfaces against each other, which is where
the detector has nothing to say.

### 1.1 The parent dashboard rendered the student dashboard's data differently

`ParentDashboard` and `StudentDashboard` read the **same** `useStudentDashboardData`
hook and present the **same** two headline figures. PH11.11 brought the student
side onto an announced placeholder, a real failure state and a metric tile; the
parent side was left with a silent grey bar, a muted failure paragraph sitting
directly above the empty-state paragraph, and `N/A` after a failed request.

The same subject's record rendering two ways is not a visual variation — it tells a
reader the two pages measure something different. Parent now uses the same
`MetricCard` shape and the same three states.

### 1.2 One hand-rolled copy of the alert markup left

`ParentAssessmentsPage`'s question-detail error rendered its own `role="alert"` div
with the shared alert's classes but none of its icon — the only failure in the
parent surface that looked different from every other failure in the app. It now
uses `ErrorNote`.

### 1.3 A tab strip with the same label in two places

`AdminAcademicsPage` kept a label-only `TABS` array and, after PH11.11 moved it onto
the shared `Tabs`, recovered each label with
`TABS.find(t => t.id === …)!.label` — seven linear scans, seven non-null
assertions, and two places to change whenever a tab is added or renamed. Id, label
and content are now declared once, typed so the tab state and the panels cannot
drift apart.

### 1.4 Checked and deliberately left alone

- **`AcademicsLandingPage.tsx` is unreachable.** PH11.9 removed `admin` from
  `/app/academics`, so nothing routes to it. Deleting dead code is unrelated
  cleanup; it stays.
- **Data tables still scroll horizontally** on narrow screens and were not
  converted to cards, per PH11.2 §12.4.
- **No stale "planned feature" copy remains.** The one placeholder that used to
  describe shipped functionality as future work was corrected in PH11.9.
- **Card title typography is unchanged.** `CardTitle` became a heading; its classes
  did not move.
- **`w-fit` → `w-full` on `SelectTrigger`** (PH11.11) is the one deliberate visual
  change in this stretch, and it is the correction of a defect: at content width a
  select sat narrower than the column holding it on roughly twenty call sites.

## 2. PH11.13 — Frontend regression

### 2.1 A stale smoke assertion, failing since PH11.9

`npm run smoke` was **already failing** at the phase baseline and had been since
PH11.9:

```
FAIL admin navigation includes the academics route
SMOKE FAILED: 1 assertion(s) failed
```

PH11.9 moved the administrator's academic structure to `admin/academics` and removed
`admin` from `/app/academics`, but the smoke assertion was never updated.

The correction asserts the route that exists **and** pins the removal PH11.9 made
deliberately — `admin` must *not* see the student/faculty Academics route, because
that page resolves a `StudentProfile` an administrator does not have. This is a
stronger pair of assertions than the one it replaces, not a weaker one.

`npm run smoke` now passes.

### 2.2 Regression coverage added

| Test file | What it now pins |
|---|---|
| `components/feedback/Feedback.test.tsx` | `PendingRegion`/`PendingMetric` announce and leave the caller's placeholder untouched; `UnavailableMetric` says "Unavailable" and is never `N/A` or `0` |
| `features/parent/ParentSupportRoute.test.tsx` (new) | The three picker states; a failed roster never claims the account has no linked children |
| `features/guidance/GuidanceDashboard.test.tsx` | A failed alerts request is announced as a failure, the empty state appears only on success, and loaded alerts survive a refetch |
| `components/charts/charts.test.tsx` | `SectionPerformanceChart` states its unit as points out of 100 and never as a percentage; an ungraded section is not plotted as zero |
| `features/auth/AuthContext.test.tsx` | Session expiry is flagged for the sign-in page, and the flag is cleared on a successful sign-in |
| `components/ui/form-field.test.tsx`, `components/ui/card.test.tsx` | Added with the PH11.11 primitives |

Baseline was 615 tests / 37 files. Now **666 tests / 41 files**.

### 2.3 Assertions re-scoped, and why each is not weaker

A change to a shared component can make a loose text match genuinely ambiguous. In
each case the assertion was tightened rather than dropped.

| Site | Change | Why it is not weaker |
|---|---|---|
| `AdminDashboard.test.tsx` | `getByText(/Overall Grade Average/)` → `getByRole("heading", …)` | Asserts the tile is labelled by a heading in the outline — a claim the text match never made. Still fails if the label disappears. A second test was added for the announced loading region. |
| `StudentDashboard.test.tsx`, `FacultyDashboard.test.tsx`, `ParentDashboard.test.tsx` | same, plus `getAllByRole("status")` with per-region `aria-busy` | Same, and now the placeholder's announced state is asserted too. |
| `routes.test.tsx` (2 markers) | "Choose a linked student above" → "This account has no linked children" | Follows a deliberate copy change: with no linked children, instructing the user to operate an empty picker is wrong. The assertion is still a body-unique marker, still required for a parent and still required absent for every other role. |

Every re-scope is commented at the site with what changed and why.

No test was weakened, deleted, or made to pass by relaxing a matcher.

## 5. Limitations

- **No browser or layout verification**, and none added. jsdom performs no layout,
  so nothing in §1 was confirmed by measurement. The one layout question in scope
  — the `AdminAcademicsPage` grid-clipping claim — was answered by removing the
  mechanism (`min-width: auto` on the grid item) rather than by observing it.
  PH11.11 §9 has the full statement of what this does and does not prove.
- **`matchMedia` is stubbed** in the drawer tests, so the mobile `inert` behaviour
  is verified against a stubbed viewport, not a resized one.
- **The `>500kB` chunk advisory** from `npm run build` is pre-existing and out of
  scope; no `React.lazy` or bundle work was done.
